# Bruno-Collection (abgeleitet aus `restRequests/`)

Die IntelliJ-HTTP-Requests unter `restRequests/` bleiben der Master (Source of Truth).
Diese Bruno-Collection wird daraus als **OpenCollection YAML** generiert und dient als
Alternative zum IntelliJ HTTP Client sowie zur Automatisierung per CLI.

Abgeleitet aus dem Vorgehen in `spring-6-gateway` (`restRequests/bruno`), angepasst auf diesen
Single-Service (Port `8083`, Auth-Server `9000`).

## Umfang

Konvertiert werden die Beer-/Customer-Flows inklusive der Controller-Fehlerfälle (22 Requests):

- `beer-flow-create-get-delete`
- `beer-flow-list-update-delete`
- `beer-flow-patch`
- `beerControllerRequest`
- `customer-flow-create-get-delete`
- `customer-flow-list-update-delete`
- `customerControllerRequest`

Die Utility-Requests `actuator.http`, `openapi.http` und `authServerRequest.http` bleiben
bewusst IntelliJ-only: Sie brauchen keine bzw. eine andere Authentifizierung und werden daher nicht
in die Collection aufgenommen.

## Struktur

```text
restRequests/bruno/
├── opencollection.yml          # Collection-Root inkl. OAuth2 + Traceparent-Pre-Request
├── environments/
│   ├── local.yml               # Port 8083, Auth-Server 9000
│   └── k8s.yml                 # NodePorts 30083/30900
├── beer-flow-…/                # generiert, ein Request pro Datei
├── customer-flow-…/
├── beerControllerRequest/
├── customerControllerRequest/
└── tools/
    ├── http-to-bru.mjs         # Generator .http -> .yml
    ├── package.json            # @usebruno/filestore
    └── package-lock.json
```

## Voraussetzungen

- Bruno CLI `4.x` (`@usebruno/cli`), Node.js ≥ 18.
- Bruno Desktop (optional).
- Für die Generierung: `npm ci` in `restRequests/bruno/tools`.

## Öffnen in Bruno Desktop

1. In Bruno Desktop **„Collection öffnen"** wählen.
2. Den Ordner `restRequests/bruno` mit `opencollection.yml` auswählen.
3. Environment `local` (oder `k8s`) auswählen.

## Ausführen

Vom Collection-Root (`restRequests/bruno`):

```bash
# ein Flow
bru run beer-flow-create-get-delete -r --env local

# alle Flows
bru run . -r --env local

# k8s-Profil (NodePorts)
bru run . -r --env k8s
```

Hinweis: Die Flows sind zustandsbehaftet (Runtime-Variablen, create/delete, Token). Ein späterer
Schritt (z. B. `02-get-the-created-beer`) kann nicht allein gestartet werden, sondern nur im
Flow-Verbund. Runtime-Variablen überleben nur einen CLI-Lauf.

## OAuth2

Die Client-Credentials-Konfiguration liegt auf Collection-Ebene in `opencollection.yml` und wird
von allen Requests geerbt (`auth: inherit`). Die Requests enthalten kein Secret.

Secret-Auflösung (Collection-Pre-Request):

```text
BRUNO_CLIENT_ID     → clientId     (Fallback: Wert aus dem Environment)
BRUNO_CLIENT_SECRET → clientSecret (Fallback: "secret" für die lokale Dev-Umgebung)
```

In CI:

```yaml
env:
  BRUNO_CLIENT_ID: ${{ vars.BRUNO_CLIENT_ID }}
  BRUNO_CLIENT_SECRET: ${{ secrets.BRUNO_CLIENT_SECRET }}
```

Oder pro Lauf: `bru run . -r --env local --env-var clientSecret=...`.

## Konvertierung (IntelliJ → Bruno)

Einmalig `npm ci` in `restRequests/bruno/tools`, danach aus `restRequests/bruno`:

```bash
# generieren (Utility-Requests sind per Default ausgeschlossen)
node tools/http-to-bru.mjs --no-folder

# nur prüfen (Exit 1 bei Abweichung)
node tools/http-to-bru.mjs --no-folder --check
```

Optionen des Generators:

- `--source <pfad>`: `.http`-Datei oder Ordner (Default: `..`, also `restRequests/`).
- `--exclude <namen>`: Komma-getrennte `.http`-Dateinamen, die übersprungen werden
  (Default: `actuator.http,openapi.http,authServerRequest.http`).
- `--no-folder`: schreibt kein `folder.yml`; die OAuth2-Definition bleibt in `opencollection.yml`.
- `--format <bru|yml>`: Ausgabeformat (Default `yml`).
- `--check`: schreibt nichts, Exit 1 bei Abweichung.

Der Generator übersetzt u. a.:

|                   IntelliJ                   |                 Bruno                  |
|----------------------------------------------|----------------------------------------|
| `### Name` + Request-Zeile                   | `info.name` + `http`-Block             |
| JSON-Body                                    | `http.body` (type `json`)              |
| `< ../scripts/traceparent.js`                | Collection-Pre-Request                 |
| `< {% … %}`                                  | `runtime.scripts` (before-request)     |
| `> {% … %}`                                  | `runtime.scripts` (tests)              |
| `client.global.set/get`                      | `bru.setVar/getVar`                    |
| `client.test` / `client.assert`              | `test(...)` / `expect(...).to.be.true` |
| `Authorization: Bearer {{$auth.token(...)}}` | entfällt, `auth: inherit`              |

Generierte `.yml`-Dateien tragen den Marker `Generated by tools/http-to-bru.mjs` und sollten nicht
manuell bearbeitet werden. `opencollection.yml` und `environments/*.yml` sind handgepflegt.

## Pflege-Workflow

1. Änderung am Master in `restRequests/*.http` (und ggf. `.md`).
2. `node tools/http-to-bru.mjs --no-folder` ausführen.
3. Diff prüfen, `bru run … --env local` gegen den laufenden Service ausführen.
4. `node tools/http-to-bru.mjs --no-folder --check` in der CI verwenden, um Drift zu erkennen.

## CI

`.github/workflows/deploy-and-test-cluster.yml` führt nach Helm-Deploy und `helm test` einen
Bruno-Smoke-Test als Pflicht-Gate aus:

1. `actions/setup-node` + `npm install -g @usebruno/cli@4.2.1`
2. `kubectl port-forward` für den Service (`:8083`) und den Auth-Server (`:9000`)
3. `bru run . -r --env local` (JUnit-/HTML-Report, `--reporter-skip-all-headers`)
4. Upload des Reports als Artifact `bruno-reports`
5. Publish der JUnit-Ergebnisse via `EnricoMi/publish-unit-test-result-action` im Checks-Tab
6. HTML-Reports auf GitHub Pages (Job `publish-bruno-report`)

`BRUNO_CLIENT_ID` (Repository-Variable) und `BRUNO_CLIENT_SECRET` (Secret) können gesetzt werden;
ohne Werte greifen die Dev-Fallbacks `messaging-client`/`secret`.

### GitHub Pages

Der Job `publish-bruno-report` baut ein `_site` mit `index.html` und den HTML-Reports und
veröffentlicht sie über die offiziellen Pages-Actions.

Einmalige Voraussetzungen:

- **Settings → Pages → Build and deployment → Source: GitHub Actions**.
- Falls das `github-pages`-Environment Branch-Regeln hat: den deployenden Branch erlauben.

Hinweise:

- Es wird immer der **letzte Lauf** veröffentlicht (vorherige Reports werden überschrieben).
- Die Bruno-HTML-Reports laden Vue/Naive UI von `unpkg.com` — der Browser braucht Internetzugang.
- `--reporter-skip-all-headers` entfernt Auth-Header; Request-/Response-Bodies sind weiterhin im
  Report. Bei öffentlichem Repo sind die Pages damit öffentlich.
